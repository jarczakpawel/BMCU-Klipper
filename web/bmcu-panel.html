Firmware flash
Expert firmware flashing - select USB or TTL bootloader.

          
!
Danger - firmware flashing can reprogram the wrong device
Be extremely careful with every flash method. Selecting the wrong device or serial port can erase or reprogram another printer/controller device. The safest option is to flash the BMCU from a PC or phone with only the intended BMCU or adapter connected. When flashing from a printer: unplug the intended BMCU or adapter, refresh the serial-port list and confirm its port disappears; reconnect it, refresh again and confirm the same port returns. Continue only if you know exactly what you are doing and have positively identified the target. This applies to both USB and TTL.

Unknown serial device selected
Do not trust the port name alone. Unplug the intended BMCU adapter and refresh - this exact port must disappear. Reconnect it and refresh again - the same port must return. If you cannot prove that, do not flash it.

Snapmaker U1 tip-forming help

      

        
Profiles
Four variants are available: Normal/Flexible filament for 0.2 mm and standard 0.4-0.8 mm nozzles. Default is used unless an exact material override exists.

        
Commands
    
          
  • BMCU_PARK_HEAD - marks the point where U1 may start parking the source Head. Commands already queued after the marker can finish on that source Head while another Head is prepared. Same-Head changes wait for the tip program instead of parking.
    • 
          
  • BMCU_TEMP S205 - sets an absolute source-Head target.
    • 
          
  • BMCU_TEMP OFFSET=-15 - offsets the selected print/profile temperature.
    • 
          
  • BMCU_TEMP_RESET - restores the selected base temperature.
    • 
          
  • BMCU_HOTEND_FAN SPEED=1.0 - forces the source Head heatbreak/hotend fan to 100%.
    • 
          
  • BMCU_HOTEND_FAN_RESET - returns the hotend fan to Snapmaker automatic control.
    • 
        

        
Observed U1 cooling
On this U1, changing the target from 220°C to 205°C reduced the measured source-Head temperature from about 219°C to 205.7°C in about 10.5 s. Actual cooling depends on temperature, airflow and environment.

        
Timing preview
E-moves use the configured U1 extrusion limits and G4 is counted exactly. Temperature/fan commands and BMCU_PARK_HEAD show 0 s because they do not wait. Mechanical Head parking/picking and heater cooling are not added.

i
Filament metadata
For every used BMCU slot the generated preset sends Orca's current material type and filament colour with the print plan. The plan is emitted before the first executable command of the normal U1 start sequence. BMCU applies metadata only after the complete plan passes validation and BMCU_PRINT_COMMIT succeeds, then sends one module-wide slot update to the BMCU. Native U1 Heads are not modified. A transient metadata-sync failure does not invalidate a committed print; it is retried before the first BMCU operation. Changing a filament in Orca does not contact the printer immediately - the values travel with the sliced G-code.

          
i
Tool-change behavior
The first required source is loaded before printing. BMCU_PARK_HEAD lets a different physical Head start parking while queued post-marker tip moves finish on the source Head. Temperature/fan commands stay bound to that source Head. Same-Head changes skip the unnecessary park/pick cycle.

        


        

          
3. If you keep a custom U1 start/end program

          
The generated preset is recommended. If you merge BMCU into your own U1 program, keep this order:

          
    
            
  1. Before the normal U1 start sequence opens tool loading, submit the complete source plan. For BMCU sources T4+ include the slicer's material and colour:
    2. 
          

          
BMCU_PRINT_BEGIN SCHEMA=1 RESET=1
BMCU_PRINT_MAP TOOL=0
...
BMCU_PRINT_MAP TOOL=4 MATERIAL="{filament_type[4]}" COLOR="{filament_colour[4]}"
BMCU_PRINT_COMMIT

          
    
            
  1. At each place where U1 normally auto-loads a physical Head, use BMCU_AUTO_FEED EXTRUDER=<0..3> INITIAL_TOOL={initial_extruder} REQUIRE_PLAN=1. BMCU delegates to stock loading or loads the mapped BMCU source.
    2. 
            
  2. Orca's filament-change G-code must call BMCU_TOOL_CHANGE TOOL=<next T>. Keep your ordinary travel/preheat around it.
    3. 
            
  3. Put BMCU_PRINT_END MODE=AUTO CLEAR=0 immediately before the normal Snapmaker PRINT_END.
    4. 
          

          
BMCU_PARK_HEAD belongs inside the tip-forming movement profile, not in Orca tool-change G-code.

        


        

          
4. Do not patch an old preset

          
!
The generated sequence is one contract
Do not copy only the internal profile marker into an older preset. Import the current JSON or bundle and reslice.

        

        


        

          

            
1. Printer and PTFE routing

            
    
              
  1. Route every BMCU Channel that physically reaches the same Klipper extruder Endpoint. Channels sharing one toolhead need a real PTFE combiner.
    2. 
              
  2. Calibrate BMCU. In Generic toolhead integration, choose the real Klipper extruder and a real toolhead sensor when one exists.
    3. 
              
  3. Select the required Toolhead preparation macro. BMCU calls it only after SEND OUT reaches the toolhead boundary and the route is in Preparing / BEFORE_ON_USE. The macro owns the complete printer-side load: heating, extruder capture, movement to the melt zone/nozzle and any final seat or prime. It must return only when the filament is physically print-ready.
    4. 
              
  4. Select the required Before pullback macro. BMCU calls it while the route is in BEFORE_PULL_BACK. The macro owns the complete printer-side unload: heating, tip forming or cutting, hotend retraction and release from the extruder. It must return only when BMCU may safely start the long PTFE pullback.
    5. 
              
  5. Both macros receive ENDPOINT, MATERIAL and REASON. Generic BMCU never adds hidden extruder distances, temperatures, prime moves, tip-forming or cutter geometry around them.
    6. 
              
  6. Toolchanger Select/Verify/Deselect and extra route sensors are optional under Advanced. A normal single-extruder printer leaves them at None.
    7. 
              
  7. Without a toolhead filament sensor, BMCU pauses immediately when its input becomes empty. Insert replacement filament into the same Channel and use the printer's normal Resume; BMCU performs Load first and only then releases Resume.
    8.

T0 / Orca slot 1 is External - manual filament. BMCU sources use their persistent T1+ assignments. Use only the slots shown below.

            
The start block shown below also sends filament_type[] and filament_colour[] for used BMCU slots. BMCU stages these values with the route and updates the Channel material/colour in the panel only after the complete plan commits successfully. T0 External is intentionally not synchronized. Changing a filament in Orca does not contact the printer immediately - the values travel with the sliced G-code.

            

            
External is intentionally manual: BMCU does not ask for load/unload confirmation and does not pretend to know whether manual filament remains in the tube. Do not mix T0 External with BMCU T1+ in an unattended automatic multi-material print unless your own printer G-code explicitly handles the manual source transition.
